> 本文与 `baseline_v2*.json` 保留修复前结果。后续修复见 `SOURCE_GROUNDING_FIX.md`，当前命令运行的是 v3 实现。

审计日期：2026-09-30。范围：离线 Python 评测数据与诊断链路；未改动生产检索、生成算法或原评分阈值，未调用在线模型。

## 1. 原基线为什么不能直接作为质量结论

保留原文件于 `golden_dataset_legacy.json`，审计明细于 `legacy_dataset_audit.json`。

- 原文件实际为 **105 条**（60 合成 + 25 边界 + 15 对抗 + 5 种子）；旧脚本截取前 100 条，遗漏最后 5 条种子。
- 自动审计发现 **16 组同题多上下文**，问题没有版本标识，却对应不同政策金额或比例。
- **11 条标准答案未通过内部完整性/数值出处检查**，主要涉及把错误对抗候选写入标准答案。
- 所有 105 条缺少来源 ID；这是新增可追溯基线所需字段，不应单独解释为旧系统业务缺陷。
- “零起付线”分支没有更新实际上下文、答案和实体；“多重条件”分支提问新增退休待遇但没有相应证据。
- 对抗候选既没有独立字段，也未被旧端到端脚本作为实际答案评分；部分条件删除没有生效。
- 旧脚本将高词项覆盖等同于检索正确，可能把错版本检索误判为生成问题；退出码只看剪刀差，也会漏掉单纯检索失败。

修正前的旧脚本结果为 64/100 通过、36 条剪刀差。由于数据、文档去重和验收口径均发生变化，不能将其与新结果直接计算性能提升幅度。

## 2. 本次建立的基线

默认恰好 100 条：55 合成、25 边界、15 对抗、5 种子；共享来源去重后为 69 个文档块。

1. 合成问题与上下文共同标注可见的虚构政策版本；检索仍通过问题文本进行，不使用样本 ID 或金标准 ID 强行选文档。
2. `ground_truth_answer` 始终保存正确答案，错误候选单独写入 `candidate_answer`。条件删除选用确实含例外条款的种子。
3. 零起付线同步更新上下文、答案、实体；移除无证据的退休待遇追加问题。问题明确询问评分要求中的基础待遇与封顶线。
4. 正式运行前审计重复 ID、同题多上下文、来源冲突、缺失字段、标准答案一致性和无效变异。审计失败即停止输出质量指标。
5. 独立核验来源文档 Hit@K；原有词项覆盖指标保留，不再用它代替来源命中。
6. 同时运行真实检索与正确上下文对照，并对生成答案增加“相对目标政策文档的数值支持”检查。
7. 错误候选独立跑评分器检出测试，使用原始完整性阈值 0.8。门禁要求数据审计、每条问答检查及全部错误候选检出均通过。

完整报告：`baseline_v2.json`、`baseline_v2_top1.json`。每条记录包含问题、预期来源、召回来源、实际答案、对照答案、评分明细及失败类别。

### A. 数据问题：当前自动审计为 0

仅表示当前规则可检测的数据一致性问题已消除，不代表已经完成真实业务专家标注或语义审查。

### B. 检索来源缺失：0 条

目标政策均在 Top-3 中，但另两条是其他版本文档。版本标识使本基线偏向明确文档定位，不代表模糊语义检索能力。需要后续另建真实业务测试集评估泛化。

### C. 多文档上下文污染：100 条

正确上下文对照全部通过，Top-3 生成却把其他版本的数值一起输出。现有抽取器保留含数字或共享词项的段落，合成器据此拼接；忠实性检查只验证数值是否出现于整个召回上下文，因此错误版本的数字也能通过。

例：`syn-000` 应回答 `policy_a` 的三级医院起付线 **200 元**、报销 **55%**、封顶 **20 万元**。实际召回还包含 `seed_b` 和 `policy_d`，答案同时列出其他版本的 **1200 元**、**1000 元**和 **10 万元**等数值。

这里的“污染”是目标政策问答约束下混入其他版本信息的诊断标签，不等于全部数字凭空捏造。修复方向应是来源范围约束、事实选择与答案相关性验证；Top-1 只用于隔离原因，不能替代通用多文档 RAG 修复。

### D. 评分器漏检：2 条

`adv-001-实体缺失`、`adv-013-实体缺失` 各缺少 5 个要求实体中的 1 个，完整性恰好为 **0.8**，满足原有 `>= 0.8` 阈值；其余数字仍有出处，因此被放行。

这需要后续明确“必答字段必须齐全”与“平均实体覆盖达标”的业务口径，不能只凭调低/调高总体阈值宣称修复。本次保留原阈值并将漏检纳入门禁。

## 4. 复现与测试

从项目根目录执行：

```bash
python -m rag_eval.data_generator
python -m unittest discover -s tests -q
python -m rag_eval.scissors_check --dataset golden_dataset_100.json --output reports/baseline_v2.json
python -m rag_eval.scissors_check --dataset golden_dataset_100.json --top-k 1 --output reports/baseline_v2_top1.json
```

生成器固定种子 42；完整数据内容可复现。核心测试 **126/126 通过**，包括新增的 11 项数据一致性、污染反例、归因及 CLI 门禁测试。两条质量基线命令应返回 1，不应忽略该退出码。

本次完成的是可信基线与失败定位。生产链路的来源约束、必答字段规则及真实业务语义评测仍需后续处理。数值出处检查无法证明主客体归属、非数值事实真实性或完全相关性。
